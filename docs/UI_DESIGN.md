# 訪問のアトリエ Web版 UI設計書

作成日：2026年10月4日  
版：初期設計 0.2

本書は目標のデザイン仕様です。実装と画面確認の結果は[実装状況](IMPLEMENTATION_STATUS.md)を参照してください。

Web版はデスクトップ版「訪問のアトリエ」のデザインを継承します。生成りの背景、オリーブ色、余白、丸み、浅い影、書体、訪問カードを共通の基準にします。ログイン・営業所切替・勤務希望・地図などの追加画面も、この基準に揃えます。

機能と権限は[基本設計書](../DESIGN.md)、実装構成は[技術設計書](TECHNICAL_DESIGN.md)に従います。本書は実装時の基準として使用します。

## 書体と余白

書体は既存と同じNoto Sans JPを `AtelierJP` として読み込み、`"Yu Gothic UI", sans-serif` を代替にします。Web配布用のフォントファイルとライセンスを確認して同梱し、外部フォント取得に依存させません。

既存の主見出し25px、太さ600を基準にします。Web版の本文・操作ラベルは14pxを基本、スマートフォンの入力文字は16pxを基本とします。時間などの補足表示は12pxを目安にし、従来の小さな文字を拡大する場合はカードの高さや幅も広げます。これらの文字サイズはWeb版での調整方針です。

PCのコンテンツ余白は上30px・左右34px、パネル内は22〜24px、カード間は16〜20pxを基準にします。狭い画面では外側の余白を16px程度まで縮めます。線画アイコン、150ms程度の色・影の変化、押下時の浅い沈み込みも継承します。

## PCの画面構成

左サイドバーは幅232px、トップバーは高さ66pxを基準とし、右側にページ見出し、概要カード、操作列、一覧またはシフト表を置きます。文字や操作が収まらない場合は高さを増やし、文字を潰して合わせません。

| 領域 | Web版での扱い |
| --- | --- |
| ブランド | サイドバー上部に既存のロゴと名称を表示 |
| ワークスペース欄 | 会社名と営業所選択。オーナーは「すべての営業所」と各営業所を切り替える |
| 管理者の対象切替 | 対象会社・オーナーの管理範囲を上部に明示し、その後に営業所を選択 |
| ナビゲーション | 既存の「予定」「利用者・スタッフ」「設定」のまとまりを継承し、権限に応じた画面を表示 |
| トップバー | 現在の画面、保存状態、予定変更のお知らせを表示 |
| サイドバー下部 | ログイン中の利用者と役割、アカウントメニューを表示 |
| フッター | ブランド名とWeb版のバージョン表記 |

営業所の選択は表示対象のフィルターです。切替で権限が増えることはなく、メンバーには所属先と本人が閲覧できる予定だけを表示します。旧版の「このパソコンに保存」「ログイン不要・SQLite」はWeb版の表示に持ち込みません。

## 訪問予定とカード

日・週切替、担当者別・利用者別切替、日付移動、今日、訪問追加の並びを引き継ぎます。概要カードは淡い緑・砂色・桃色・青灰色を基準とし、各カードの意味を見出しで示します。

| 訪問状態 | カード背景 | 左側の線 | 表示 |
| --- | --- | --- | --- |
| 仮予定 | `#f4eedb` | `#bfab79` | 仮予定 |
| 確定 | `#eaf0df` | `#8ca474` | 確定 |
| 完了 | `#e5eff0` | `#8aa8ad` | 完了 |
| 中止 | `#f0eee4` | 同系色の枠 | 中止。通常表示への掲載条件は業務仕様に従う |

最初の3行は既存カードの配色、中止は既存の状態ラベルを基にしたWeb版の表現案です。カードには時刻、利用者名、業務、状態を表示し、複数営業所をまとめて表示するときは営業所名の小さなラベルを追加します。営業所の識別で訪問状態の色を上書きしません。

週表示は担当者を縦、日付を横に配置し、名前の列を固定します。表は最小幅1110pxを基準に、文字量に応じて拡張します。狭い画面では表の領域を横スクロールできるようにし、カードを極端に縮めません。日表示は担当者と時間軸の既存構成を引き継ぎます。

ドラッグ中は元カードを薄くし、移動先を淡い緑と枠で示します。日付・担当者・時間の変更をプレビューし、保存中・保存成功・競合を区別します。エラー時は元の位置に戻して理由を表示し、既存の重複・勤務・移動の検証を省略しません。ドラッグと同じ変更は編集ダイアログからも行えます。

## 入力と追加画面

| 画面・部品 | デザインと操作 |
| --- | --- |
| ログイン | 生成りの背景にブランドと一枚のパネル。ログインID・パスワード・主ボタンを縦に配置 |
| スタッフ・顧客の一覧 | 既存の丸いアバター、情報カード、淡いタグを使用。検索・営業所フィルターは共通の操作列へ配置 |
| 編集ダイアログ | PCは関連する項目を2列、狭い画面では1列。見出しと説明、入力、キャンセル・保存の順に配置 |
| 対応業務・所属営業所 | 選択肢をラベル付きチェックボックスまたはチップで表示し、選択肢単位で次の行へ折り返す |
| 勤務希望 | 日付ごとに勤務可・不可・希望休と時間帯を編集。未提出・提出済み・差し戻しを文字でも表示 |
| 代理入力 | 募集月のスタッフ行に「代理入力」。広いダイアログに対象氏名と対象月を明示し、本人と共通の希望入力欄を使用。保存後に代理提出。提出済みは理由付きの「差し戻して編集」 |
| オーナー本人 | 「自分の予定・希望」をオーナーのメニューに追加。初回に既存スタッフ選択・新規登録、その後は本人プロフィールと「自分の勤務希望」「自分の訪問予定」の切替。新しいアカウントは作らない |
| 顧客地図 | PCは地図と利用者一覧を並べ、選択したピンとカードを連動。操作列、カード、ボタンは他の画面と統一 |
| 訪問先の詳細 | 住所、入口・駐車場所などの案内、当日の訪問時刻、外部地図を開くボタンをまとめる |
| 位置の取得状態 | 「位置を取得中」「位置の確認が必要」「取得できませんでした」を入力欄の近くへ表示 |
| 空・読込・失敗 | 同じパネル内で状態と次の操作を説明し、入力内容を保持したまま再試行できるようにする |

チェックボックスの箱は縮ませず、短い選択肢のラベルを一文字ずつ縦に折り返しません。長い業務名は十分な横幅を確保した選択肢内で複数行表示します。氏名・住所は必要に応じて折り返し、省略時も詳細画面で全文を確認できるようにします。

地図のピンは主色を基準とし、選択中のピンは形・枠でも識別します。地図の提供元表示を隠さず、地名・道路・建物を読める地図スタイルを選びます。表示範囲は役割に従い、メンバーには自分の担当訪問先だけを表示します。

## スマートフォンへの調整

初期の切替目安は、1200px以上を通常PC、768〜1199pxを狭いPC・タブレット、767px以下をスマートフォンとします。中間幅はサイドバーを開閉式にしてカードを2列へ、スマートフォンは1列へ変更します。実装時に日本語の実データで境界を調整します。

メンバー画面は「今日」「シフト」「勤務希望」「地図」の4項目を下部に配置し、お知らせとアカウントは上部から開きます。オーナー・管理者は開閉式のメニューから各管理画面へ移動します。色・書体・カード・ボタンの形はPC版と共通です。

操作領域は44px程度以上を確保します。ダイアログは画面内に収まる幅と高さで内部スクロールを使い、ソフトウェアキーボードや下部メニューが保存ボタンを隠さない配置にします。地図の詳細は下から開くパネルとし、閉じる操作と地図へ戻る操作を明確にします。

メンバーのシフトは日別の一覧を初期表示にします。週表を使う場面では表だけを横スクロールし、ページ全体が左右へずれないようにします。タッチ操作やキーボード操作でも編集画面から変更でき、ドラッグだけに依存させません。

## 実装と確認の基準

Reactの共通部品としてサイドバー、トップバー、ボタン、入力、ダイアログ、タグ、状態ラベル、訪問カード、通知を作成します。色・角丸・影・余白・書体は共通のテーマへ集約し、業務画面ごとの個別指定を増やしません。

実装時は、次を受入条件として確認します。

1. PCの訪問予定を既存版と同じ表示条件で並べ、背景、ブランド、配置、ボタン、カードの印象が揃っている。
2. 1440×900、1280×720、390×844を代表寸法として、文字切れ・操作の重なり・画面外の保存ボタンがない。
3. 長い氏名、営業所名、業務名、住所、多数の所属・担当業務でも、文字が一文字ずつ縦に並ばない。
4. 通常、選択、フォーカス、無効、保存中、失敗の各状態を識別でき、キーボードで操作できる。
5. 確定・完了・中止や位置取得失敗を色だけで伝えず、文字でも確認できる。
6. 権限別のナビゲーションが基本設計と一致し、営業所切替や地図から閲覧範囲が広がらない。

これらの寸法・受入条件は設計目標であり、実装済みの検証結果ではありません。
